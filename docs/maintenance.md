## 修改放在哪里

| 修改内容 | 文件 |
| --- | --- |
| 触发场景、总体工作流、关键约束 | `SKILL.md` |
| 界面名称、简介与默认提示词 | `agents/openai.yaml` |
| 输出结构、血缘要求、交互和验证规范 | `references/output-spec.md` |
| 多页总览、页面职责与导航关系 | `references/document-hub-navigation.md` |
| 人类读者介绍和操作示例 | `README.md`、`docs/usage.md` |

技能标识保持 `data-development-docs`，默认提示词保留 `$data-development-docs`。元数据与 README 可以使用中文，表名、字段名和命令保留原始标识。修改详细规则时应检查入口与参考文档是否一致，避免一份要求按需动画、另一份无条件要求自动播放之类的冲突。

## 验证技能包

如果当前环境安装了 `skill-creator`，可从本仓库根目录运行其校验器（路径不同则相应调整）：

```bash
uv run --with pyyaml python ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py .
```

此命令需要 `uv`，首次运行可能下载 PyYAML；也可用已经安装 PyYAML 的 Python 执行同一脚本。校验器来自宿主环境，不包含在本仓库。

基础校验只检查技能元数据和部分格式约束，不证明生成文档的业务正确性。另需检查 Markdown 本地链接存在、YAML 能解析、默认提示词包含技能标识，以及待上传文件不包含真实项目数据或凭据。

## 验证生成的文档

生成文档后按 [输出规范](../references/output-spec.md) 检查内容一致性、字段血缘、逻辑块与图示对应、阶段隔离和导航。HTML 需解析结构、检查脚本语法和唯一 ID；可访问浏览器时还需实际检查图的连线、窄屏布局以及节点或连线交互。

区分“技能包校验通过”和“生成文档验收通过”，不要用前者代替后者。

## 发布更新

先检查差异和待提交文件，只提交与技能相关的内容。每项更新从主题分支提交并推送，通过 Pull Request 合入 `main`；不要直接向 `main` 推送。仓库管理员应为 `main` 配置保护规则，要求通过 Pull Request 合并，并按项目需要启用审批、检查和对话解决要求。合入后核对远端 `main` 与本地技能副本一致。若本地技能目录直接是 Git 仓库，更新前先检查工作区，防止覆盖未提交修改。

仓库未附带许可证时，不应假定已经授予开源再分发许可；需要开放授权时，由维护者决定并添加适合的许可证。
