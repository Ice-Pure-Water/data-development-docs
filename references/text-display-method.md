# 规格文本处理与展示契约

本契约用于把规格 Markdown 中的事实转成适合屏幕阅读和现场讲解的文字层级。它与[文字与视觉设计准则](writing-and-visual-design.md)配合：后者规定中文表达原则；本契约规定内容如何分层、拆分和排版。每次生成 HTML 都按本契约处理文字，不把 Markdown 原样铺成连续长文，也不以放大标题、堆色块代替信息组织。

## 1. 先整理内容，再选择样式

- 以规格 Markdown 为事实基线。先完整抽取，再决定哪些内容常显、哪些内容可展开；不得为版面删掉条件、例外、来源或待确认事项，也不得为填满布局补写事实。
- 将文字分为四个阅读层级：
  1. **总览句**：业务目标、核心数据路径、结果对象；首屏可快速读完。
  2. **讲解句**：阶段目的、关键业务判断及结论；与对应流程节点同屏出现。
  3. **规则细节**：触发条件、处理原则、结果、优先级、例外和未决项；放在对应阶段详情或原位展开内容中。
  4. **参考信息**：库表字段、完整标识、来源位置、DDL 关系；放在对象、血缘或来源区，保留可检索和复制性。
- 一段只承担一个主要意思。把连续多项规则拆为独立条目；不要把同一条事实拆散到不相邻区域。保留“结论—依据/条件—结果/例外”的阅读顺序。
- 总览文字不能取代明细；明细也不重复粘贴整段总览。使用同一事实清单中的短摘要与完整说明，明确相互对应的阶段或逻辑专题。

## 2. 建立一致的文字角色

HTML 使用固定、可复用的语义角色和视觉样式；同一角色全页看起来相同，不同角色有稳定区别：

- **页面标题**：说明业务对象和方案主题。只设一个 `h1`，不加内部代号、版本号或页面功能介绍。
- **页面摘要**：一到三句说清目标、数据路径和结果；比正文略突出，控制在易扫读的阅读宽度内。
- **章节标题**：标识整体流程、关键逻辑、数据对象、字段血缘等主区域。
- **阶段标题**：左侧导航、流程图高亮节点和右侧详情使用同一名称；附一条结论式摘要。
- **逻辑标题与摘要**：标题写业务结论或判断主题；摘要写适用范围/主要结果。完整规则在对应位置展开。
- **正文**：解释业务目标、判断和关系。保持正常字重及足够行距，不把段落做成低对比的辅助文字。
- **标签与元信息**：来源、适用范围、读/写、粒度等短标签；使用较小字号但仍清晰可读，不承担关键规则。
- **技术标识**：库、表、字段、代码值、英文缩写和日期原样保留；可使用等宽字或稳定字重区分，并保证可选中、复制和换行。
- **来源文字**：链接文字说明它指向的文档或用途；避免“点击这里”“来源 1”这类脱离上下文的标签。

用 HTML 语义元素表达结构：章节用连续的 `h2`/`h3`，正文用 `p`，并列事实用 `ul`/`ol`，术语和值对用 `dl`，展开内容用 `details`。不要只为字号或粗细选择标题标签；不要用 `<br>` 堆出视觉间距。

## 3. 版面与中文排版基线

- 先按真实展示宽度优化正文，再处理标题和装饰。普通正文桌面端建议 16–18px、行高 1.65–1.8；在三栏详情区空间较窄时优先扩展详情可用宽度或压缩次要元信息，正文不得低于 15px。投影展示时应按实际观看距离适当放大。
- 阅读型正文控制在约 30–42 个汉字的行宽；摘要与说明按内容收窄。短标签和字段名允许较短；避免让长段落横跨整个宽屏。不要为套用英文字符数而把中文正文挤成窄栏。
- 使用左对齐，靠段间距和分组组织内容，不用两端对齐。连续正文行距充足；段落间距小于章节间距，章节间距小于页面区域间距，形成稳定节奏。
- 仅设置少量文字级别：正文、辅助说明、标签、标题层级。通过尺寸、字重和留白形成层级；颜色作为补充，正文使用高对比深色，关键业务结论不可只用浅色或小字表现。
- 字体优先使用稳定的系统中文无衬线字体栈，指定合理的简体中文回退字体；页面离线可打开，不依赖远程字体。英文/数字和中文混排时确认字重协调。等宽字体仅用于技术标识，不用于大段业务说明。
- 中文按自然词组换行。使用 `word-break: normal`、`line-break: strict`；`overflow-wrap: anywhere` 仅用于超长库表/字段标识、URL 等连续技术字符串。不要逐字强制断行，不截断关键标题或对象名。
- 标题可用 `text-wrap: balance`，长正文可用 `text-wrap: pretty` 作渐进增强；不支持时仍保持正常可读。避免手工插入换行去适配单一屏宽。
- 标点、括号、数字单位和中英文空格遵循中文技术写作规范。不能通过缩小字号或紧缩字距解决内容溢出；应先换行、扩宽或移动到更合适的详情位置。

## 4. 各页面区域的文字编排

- **标题区：** 标题、摘要、需求/参考链接依次呈现。摘要只讲方案内容；链接使用自然中文名称，并可在相邻短说明中交代来源类型。
- **三栏讲解区：** 左栏阶段名和摘要保持短；中栏节点只放处理动作/结论及必要的短对象名；右栏详情承载完整解释、条件和读写对象。正文与图在阅读过程中保持同阶段对应，不能让用户靠猜测判断详情属于哪个节点。
- **同层并行内容：** 使用并列列区或明确的分组标题，让同一层级的多项逻辑同时可见；避免纵向堆成长段或把每项包进同款卡片。
- **独立业务逻辑：** 每项常显标题和一句摘要；完整条件、处理、结果、例外原位展开。展开后保持标题可见和上下文连续，不弹出侧栏。
- **数据对象：** 作用行与适用范围列的标题要醒目；对象项内部按库名/完整表名、用途、粒度/主键、DDL 关系的顺序排列。字段名与说明明确对齐，不用密集的“标签：值；标签：值”长串。
- **字段血缘：** 以字段为阅读锚点，字段名显著，业务含义、来源、推导、阶段及空值/冲突边界分列组织。长表格可在自身区域滚动；表头随读者移动保持语义明确。
- **长规格页：** 按原规格章节阅读，章节开头提供结论或本节说明；长清单合理分组。避免把全部内容变成一列无层级的连续段落。

## 5. 避免降低可读性的呈现

- 不把正文压进节点、徽标、窄侧栏、过小提示文字或装饰性眉题。
- 不连续堆叠相同样式的摘要块、卡片、色块、粗体句或分隔线；样式变化应表示真实层级或关系。
- 不把每个短语都加粗、上色或大写；强调只用于结论、关键边界和读者定位。
- 不用全大写英文眉题、虚构编号、无意义标签、装饰性图标或重复序号伪造层级。
- 不将关键文字设为悬停后才出现；展开是有意的阅读动作，内容存在且可见入口。
- 不使用固定高度裁掉文本、单行省略号隐藏业务事实、过窄容器造成逐字换行，或用不透明颜色压住文字。

## 6. 呈现检查

完成 HTML 后按实际字体和布局检查：

- 首屏是否能快速说清方案目标、主要数据路径和结果；各内容区域的标题能否一眼区分。
- 正文是否清楚易读；一段是否只讲一个主要意思；同层逻辑是否并列可见；长说明是否处在合适的详情区。
- HTML 只面向电脑端展示。检查电脑端讲解布局中的中文换行、标题孤行、标点挤压、技术标识溢出、固定导航遮挡和截断内容；流程图必须完整显示在流程栏内，不得用内部横向滚动弥补空间不足。
- 检查正文、技术标识、注释、链接是否有稳定的字号、字重、颜色和行距；信息层级不能只依赖颜色。
- 对照规格 Markdown 确认文本压缩没有丢失条件、优先级、例外、来源和待确认项，且图、摘要、阶段详情讲的是同一事实。
