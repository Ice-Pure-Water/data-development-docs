# 数据流程图绘制契约

本契约是 `data-development-docs` 自带的流程图设计方法。每次生成包含数据流的 HTML，都按此流程建模、布局、布线和验收；不要求用户或后续项目安装、调用外部 diagram-design skill。具体页面风格服从用户已确认的规范；本契约提供稳定的图形表达方法。

## 1. 选择图形表达

- 目标是说明数据从哪里来、经过什么处理、分支/汇合在哪里、产出什么。优先用端到端的分层数据流程图。
- 主流程按用户要求纵向自上而下。来源并行时在同一阶段横向并列，再向下汇合。只有业务规则确实会产生不同后续路径时，才用判断节点表达分支。
- 节点形状表达节点类型，颜色表达业务类别或阶段强调。常规处理使用矩形；真实起点/终点可用圆角终端形；真实条件分支用菱形；真实汇合用明确的连接点。不要只靠颜色解释含义，也不要为了多样化而任意改变节点形状。
- 关系复杂时先确定端到端图的阶段和边界，再补充对应局部细节图；不要把总图拆没，也不把无关图形类型硬塞进流程图。

## 2. 建立可追溯的图模型

从规范规格 Markdown 生成唯一图模型，再由它同时生成 SVG 节点、连线、阶段导航和详情关联。至少记录：

- **节点：** 稳定内部键、阶段键、节点类型、可见中文标题、必要的短说明、来源位置。
- **连线：** 起点键、终点键、数据/控制关系、输入中明确时的简短关系说明、来源位置。
- **布局信息：** 阶段层级、并行组、真实分支/汇合、节点顺序依据。

绘图前输出一份完整的边清单，格式为“输入对象或上游节点 → 处理节点 → 输出对象或下游节点”。清单覆盖所有节点和边。来源关系没有依据时标为待确认，不从图形美观反推业务连接。来源有顺序时保留原顺序；无顺序的同级分支可以重排以降低交叉，平手时按来源 Markdown 出现顺序稳定排序。

## 3. 分层与排布

1. 按用户确认的阶段顺序设置纵向层级；没有显式阶段时，按依赖关系计算拓扑层级，并把每个原始处理步骤映射回来源位置。
2. 将同阶段并行节点放在同一水平带内；把共享前置节点、真实汇合节点和共有后续节点分别放在共同分支之前/之后。
3. 在不改变既定业务先后关系的前提下，调整同层节点顺序以减少边交叉。可采用分层布局中常用的邻接位置/重心排序思路，并进行上下游往返检查；每次排序结果固定，不用随机布局。
4. 依据节点文字长度确定框尺寸和水平间距。分支增加时优先扩展画布、分配独立通道、拉开节点；不缩小字号、不把长说明塞进节点。
5. 为循环或回流关系分配主流程外侧的独立回路通道；不要穿过主流程节点，也不能把回路误画成新的阶段顺序。

## 4. 连线与交叉规则

- 连接线使用正交折线；仅当端点对齐时才使用直线。所有线段与节点边垂直相接，进入节点边的直线段，不能从角点斜插。
- 先为不同路径规划专用走线通道，再绘制连线。线从节点独立的接入点出发；同一节点边上的接入点彼此分开，平行线全程保持可辨，不共用或重叠描边。
- 连线不得穿过非端点节点、标签或其他连线。标签放在留白区，距线至少 6px；有底色遮罩时，遮罩和连线之间仍留出可见空隙。
- 真正的多路汇合画到显式的汇合节点。仅仅几何相交的路径不能共用汇合点，也不能在交点加圆点。
- 交付标准为**零交叉、零重叠、零贴线**。逐一检查所有路径交点与节点进出口；任一不合格都要重排同层节点、调整通道或重新分区，不能把桥接/跨线符号当作常规补救。
- 若依真实拓扑无法在一个平面图内无交叉表达，按业务阶段或真实边界拆成相邻的局部图；在各图边界以相同的数据对象/处理节点名称标出“输出至”和“接续自”，并保留一条简洁的端到端阶段总览。局部图之间不画互相交叉的长连线。不得删边、合并不同概念或改变处理顺序来伪造无交叉结果。

## 5. 文字与数据对象

- 节点标题用自然中文短语，优先说明业务动作或业务结论。说明文字独立换行；单节点不承担多条规则的完整描述。
- 图内允许显示有助于读懂数据去向的短对象名或边标签。完整库表名、用途、粒度、主键和 DDL 关系放入阶段读写区及独立的对象作用 × 适用范围分区，不把对象列表嵌进图节点。
- 测量文本后再定框宽高。中文可按词组换行；表、库、字段等技术标识不得切断含义，必要时在节点外或详情区完整呈现。

## 6. 流向动效与颜色

- 本 skill 的流向编码遵循用户要求：不用箭头，以沿线移动的短划线或光点表示流向。底层静态线完整展示所有关系；动效不能制造来源没有定义的路径。
- 静态轨道不透明、至少 2.5px；动效线/标记至少 3px。浅底上使用可见的中深色静态线和与节点配色协调的流动色；关键线条对比度目标至少 3:1。平行分支用有限色相区分，必要时配合文字说明。
- 颜色、线型或动效均不单独承担业务语义。阶段滚动高亮只改变浅色背景带，不降低节点、静态轨道或流动线的亮度。
- `prefers-reduced-motion: reduce` 下停止动效，但显示完整、可区分的静态路径。无脚本时也能阅读图中业务信息。

## 7. SVG 与输出验收

- SVG 使用唯一且稳定的 ID；通过 `<title>` 和 `<desc>` 给出图名和端到端说明，阶段节点有可访问名称。可交互节点可键盘聚焦，并与同页详情定位对应。
- 图的绘制顺序先画连线，再画不透明节点底和节点内容，避免线路透过节点。文字、边框和路径全部落在 `viewBox` 范围内。
- 每次输出前按边清单逐项比对图中节点和边。检查每个节点是否存在、每条线是否准确、每个汇合是否真实、是否漏了孤立源/结果。
- 对连接线做几何复核：除真实连接节点外，任意两条不同路径不能相交、重叠或贴行；线路不能穿过非端点节点；端口和文字标签不能撞边或遮字。布局修改后重新复核全图。
- 在桌面宽度、窄屏和减少动态效果状态下查看图；确认线色、线宽、节点文字、图例、固定导航和阶段联动都可读。窄屏只允许流程图所在区域局部横向滚动，不允许整页溢出。
