# diagram-design 融合说明

本 skill 的流程图方法以 `cathrynlavery/diagram-design` 为上游参考，使用已核对版本 [`f2f4d49`](https://github.com/cathrynlavery/diagram-design/tree/f2f4d49/skills/diagram-design)。来源仓库采用 MIT License，见[上游许可证](https://github.com/cathrynlavery/diagram-design/blob/f2f4d49/LICENSE)。

## 融入的方法

- **先确定图的语义，再定图形。** 数据方案总图采用端到端数据流；存在并行、角色、属性融合或不同输入输出时，先用图模型说明关系，再选分层或泳道布局。
- **从显式图模型生成图。** 节点、边、分组、阶段、端口和来源位置可追溯；布局坐标和路由稳定记录，避免靠自动布局器或每次临时手绘造成漂移。
- **按真实关系排版。** 顺序、并行、分支和汇合各用清楚的空间结构表达；正交折线、独立端口和专用通道降低交叉。真实汇合才共用连接点。
- **先确保静态图完整。** SVG 的标题、说明、节点名称、静态连线和阶段关联均可读；动效只强调已存在的数据流，不补造关系。
- **用结构网格和几何复核稳定输出。** 节点按文字尺寸定框，结构尺寸采用固定网格；检查线段与节点、标签、其他线的相交、重叠和裁切。

## 本 skill 的适配规则

用户已确认的规格 HTML 约束优先于上游通用样例：浅色中文页面、整体流程纵向展开、阶段背景联动、无箭头并以沿线动效表示流向、电脑端宽版式、图内无横向滚动；数据库对象独立呈现为“对象作用行 × 适用范围列”的矩阵。流程节点配色、页面字体和对象矩阵使用本 skill 自己的统一视觉规范。

上游 skill 的深色默认皮肤、箭头、图类型默认预算、手机端局部滚动和跨线桥接不作为本 skill 的输出要求。只吸收有助于数据规格图稳定性的建模、排布、SVG 和几何方法；不把其他业务流程、示例文案或项目配色带入用户文档。后续生成直接执行 [流程图绘制方法](flow-diagram-method.md)，无需运行时联网或安装上游 skill。

## 每次重画的固定顺序

1. 从当前规格 Markdown 中提取 Mermaid、整体流程段落、阶段读写对象，建立节点和边清单；清点 Mermaid 声明与正文补充，列出来源配置、候选、中间、并行属性路径、汇合和结果。
2. 以节点键和边键映射来源文档；核对每个节点和每条连接后再分组、排层。旧 HTML 只提供页面上下文，不能当作流程事实或复用旧坐标拓扑。
3. 依据纵向主方向确定阶段带、并行泳道、节点尺寸、端口和正交通道；记录稳定坐标。若为避免交叉而在不同逻辑泳道重复画同一来源，泳道标题必须说明它是同一来源的另一条已定义数据路径。
4. 按固定的浅色调色板重画 SVG：静态轨道使用可见中深色，动线沿数据关系流动；高亮只改变当前阶段背景，不能把节点或线条灰化。
5. 逐条以 Markdown 边清单核对 SVG 的节点和路径，再做几何、文字溢出、版面宽度、SVG 可访问性和动效静态降级检查。拓扑、SVG 与阶段详情任一不一致都要修正后再交付。
