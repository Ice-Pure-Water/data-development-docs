# 文字与视觉设计准则

本参考把适用于数据方案规格的中文写作、HTML 展示和流程图方法合并到本 skill。后续项目调用时不依赖本机安装其他辅助 skill。来源只提供方法参考；本文件中的用户确认要求优先，具体项目事实始终以来源 Markdown 为准。

HTML 的文字角色、内容分层、具体排版基线和展示检查统一参照[规格文本处理与展示契约](text-display-method.md)；这里聚焦中文表达原则、总体视觉方向和语义 HTML，避免复制两套容易漂移的文字规范。

## 中文技术表达

- 先明确这段内容要说明的业务事实，再选择读者容易理解的中文名称。术语按业务上下文定，不逐词硬译英文；同一概念在规格 Markdown、图、HTML 和字段说明中使用同一名称。
- 句子短而完整。优先用主动语态和具体动词；一段先说结论，再给条件、依据和例外。并列项用列表，连续解释用段落，字段或重复结构用表格。
- 用来源中的数字、条件、对象和例子表达事实。删掉空泛形容词、开场套话、宣传语、无依据的评价和重复结论。不要用“赋能”“无缝”“全面提升”等词替代可验证的方案说明。
- 读者未必熟悉内部缩写。首次出现时用自然中文解释；库、表、字段、产品名和代码值保持原样。术语无法判定时列入术语表或标“待确认”，不自行造词。
- 规则表述明确区分条件、判断、结果、优先级、例外和待确认事项。来源没有给出的信息不补齐；不同来源冲突时并列注明来源和差异。
- 标题层级连续，不为视觉效果跳级。加粗、列表和括号只用于帮助定位信息。中英文、数字、单位和标点保持全文一致；可用已安装的格式工具辅助，但不新增工具依赖，也不因格式修正改变技术标识。
- 避免模板化 AI 语气：少用空洞过渡句、机械三段排比、夸张评价和“不是 A，而是 B”式对照。直接说方案采用什么、依据是什么、边界在哪里。

## HTML 阅读与视觉方向

- 先从内容、讲解场景和已确认偏好确定页面的视觉方向，再定义一组精简的颜色、字体、间距、线条和布局变量。用户明确指定的视觉要求优先；没有指定的部分按当前业务内容作出有理由的选择，不复制固定模板或其他项目的整体外观。
- 让内容结构决定表现方式：顺序流程用纵向流程图，关系网用关系图，重复字段用表格，数据对象按“对象作用为行、适用范围为列”做对齐分区。对象区不使用 HTML 表格或卡片。页面是方案展示与讲解材料，不做通用仪表盘，不把内容切成同质卡片墙。
- 重要内容优先于装饰。通过标题层级、留白、对齐、字体和少量稳定色彩区分信息；正文与节点文字清晰易读。避免渐变、阴影、颜色、图标、眉题或编号只为装饰而存在。
- 文字是信息，不是装饰。标题概括具体业务主题；链接说明目的；摘要使用来源事实；不要放无作用按钮、虚构数字、占位文案或未实现的交互。
- 使用语义化 HTML 和正确的标题顺序。流程图采用 SVG/HTML 等可读结构；图有名称与文字说明。操作元素能用键盘访问，有清楚焦点；颜色对比足够；动画支持减少动态效果设置。无脚本时主要规格内容仍可读。
- 按桌面展示和窄屏阅读分别安排结构。密集图在局部容器内滚动或平移，不把整页撑出横向滚动；长表只在自身容器横向滚动。检查节点换行、连线避让、固定导航遮挡、标题裁切和长标识溢出。
- CSS 使用集中定义的变量和单一规则来源。修改已有规则，不层层追加互相覆盖的补丁。页面自包含，离线可打开，不依赖远程字体、CDN 或构建服务。

## 流程图布局与数据流表达

- 先按来源事实列出“输入对象 → 处理节点 → 输出对象”的关系，再布置图形。线条只能表达明确的数据流或处理关系；图中每个主要输入、分支、汇合与结果都要有可追踪的去向。
- 主流程纵向、自上而下。真正并行的来源或逻辑可以在同层横向并列，再向下汇合；不得为了排版把主方向改成横向，也不得把并行关系画成串行。
- 关系建模、分层、同层排序、正交通道、交叉消除和几何验收统一按[内置流程图绘制方法](flow-diagram-method.md)执行。不能仅凭人工目测判定连线清楚；在拓扑允许时交付图要求零交叉、零重叠、零贴线，密集拓扑按该方法处理并保留端到端关系。
- 节点使用简短中文动宾结构或业务结论。辅助说明另起一行；长内容扩宽节点、换行或移到同步的详情区。节点边框必须容纳文字，不能裁切或溢出。
- 用户已确认的流向方式是沿线动效，不使用箭头。静态轨道至少 2.5px、保持不透明并使用可见的中深色；动效线/移动标记至少 3px，使用与节点协调且容易辨认的颜色。关键连线对比度目标不低于 3:1；线条仍不清楚时优先加深、加粗和拉开分支间距，不通过灰化或降低透明度处理。动效方向严格符合数据关系，平行线可错开节奏。阶段高亮只加浅底，流程图原有节点和连线配色保持稳定。减少动态效果时显示完整静态流线。
- 总图在页面阅读时持续可见，并与左侧阶段导航、当前阶段背景高亮、右侧详情和读写对象同步。阶段和图节点可定位到同页相应内容，不打开侧栏或跳出当前页面。
- 不把数据库/表字段清单放进流程节点。图可在节点旁标简短来源/结果对象名；完整对象、用途和 DDL 关系放在独立的行列分区及阶段读写说明。

## 输出前的针对性检查

- **事实：** 规格 Markdown 和 HTML 没有增加来源未支持的业务条件、映射、表、字段或结论。
- **中文：** 术语一致，英文缩写已按需要解释；句子直接，删除套话和模糊修饰词。
- **层级：** 标题能概括内容，先展示方案核心，再逐层显示规则和字段细节。
- **流程：** 阶段导航、图、详情与数据对象读写关系一致；主流向竖直，分支、并行和汇合准确。
- **可读性：** 节点文字未溢出，连线不穿字、不遮节点；静态线和动效线对比清楚、没有低透明度淡灰线；窄屏排布和键盘焦点可读。
- **实现稳定：** 页面离线可打开；减少动态效果后流程依旧清楚；没有为视觉效果加入无功能控件。

## 方法来源

本节概括并适配以下公开方法，只吸收与数据规格写作和单页 HTML 展示有关的部分；不复制其模板、品牌视觉或与当前任务无关的交互：

- [leter/zh-tech-writing](https://github.com/leter/zh-tech-writing)：短句、平实中文、具体事实、术语和 AI 腔清理。
- [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)：视觉方向由主题和使用场景决定，形成明确的设计选择并减少模板化装饰。
- [plannotator/effective-html](https://github.com/plannotator/effective-html)：自包含 HTML、内容优先、语义结构、响应式和无障碍设计。
- [alchaincyf/huashu-design](https://github.com/alchaincyf/huashu-design)：真实内容驱动版式、重视文字排版，并检查实际浏览器中的呈现效果。
- [diagram-design](https://github.com/cathrynlavery/diagram-design/tree/main/skills/diagram-design)：其适用于本任务的关系建模、布局、连线和 SVG 方法已经整理为[本 skill 的内置流程图规范](flow-diagram-method.md)，生成时不需要另行加载外部 skill。
- [MDN：Semantic HTML](https://developer.mozilla.org/en-US/curriculum/core/semantic-html/) 与 [MDN：HTML accessibility](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Accessibility/HTML)：正确使用语义元素、标题层级、链接文本、键盘可达性和图文替代说明。

用户对当前 skill 的明确规则高于这些通用参考。例如，常见流程图工具使用箭头，但本 skill 的方案图使用动线表现流向且不画箭头；数据对象按角色和适用范围的行列关系展示，但不用 HTML 表格或卡片。
