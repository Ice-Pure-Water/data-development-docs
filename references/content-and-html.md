# 规格内容与 HTML 展示

## 规格 Markdown

规格 Markdown 是唯一事实基线。用户提供 Markdown 规格模板时按其章节组织；否则按实际内容组织以下章节，不为填模板编造信息：

1. 方案标题与摘要；2. 需求、参考和来源；3. 整体数据流程；4. 阶段处理方案；5. 可独立讲解的业务规则；6. 数据对象；7. 字段血缘；8. 必要的术语和待确认事项。

从来源逐项提取目标、阶段、分支/并行/汇合、读写关系、所有独立判断、对象角色与范围、字段来源及推导、链接、冲突和未决口径。去重但不丢边界；冲突并列标“待确认”。关键事实记录来源章节、文件或链接。

## HTML 内容模型与固定页面

从规格 Markdown 建立一份内容清单（manifest），再据此生成主页各区。至少包含标题摘要、来源链接、阶段及数据流关系、逻辑专题、对象角色/适用范围/DDL 关系、字段血缘和来源定位。阶段导航、主图、阶段详情和读写对象必须共用阶段及对象记录，不能分别手写造成不一致。

HTML 页面必须从 [`assets/html-page-template.html`](../assets/html-page-template.html) 开始生成。模板是页面布局、组件、CSS 变量、字号、间距和交互的唯一来源；不同业务只替换事实内容和数据图，不得重新选主题、换页面布局、另造对象样式或增加局部 `<style>`。inline 样式仅允许模板对象矩阵自带的 `--scope-count` 动态列数。diagram-design 负责数据图自身的拓扑和图形规范，不改变全页设计系统。页面 CSS 中已有值需要调整时，先说明该值造成的具体可读性问题，再只改模板中的对应 token，并同步更新模板规则。

内容清单使用稳定字段，不在 HTML 中临时散写重复数据：

- 页面：`title`、`summary`、`sourceLinks`。
- 阶段：稳定内部键、中文名、摘要、来源锚点、读取对象、写入对象、详情和图中节点。
- 逻辑专题：稳定键、结论式标题、一句摘要、条件/处理/结果/边界及所属阶段。
- 对象：完整库表名、对象作用、适用范围、用途、粒度/主键、DDL 关系和来源位置。
- 字段：目标字段、含义、来源及推导、阶段、空值/冲突边界。

同一事实只维护一份；阶段导航、图节点、右侧详情、读写对象和相应专题由这些记录引用。内部键只作锚点，不向读者展示。

填充模板时只替换内容插槽，保留外层元素、`class`、属性和顺序。右侧每个阶段用 `<article class="phase-detail" data-stage-detail="阶段键">`，标题用 `h2`，读写对象放在 `.phase-objects` 内，按 `.object-io` 的“读取/写入”两类分行；每条业务逻辑使用 `<details class="logic-item">`，摘要标题和结论分别放在 `<summary>` 与 `.logic-summary`。对象矩阵按模板 CSS Grid 行列组件输出，字段血缘只使用 `.lineage` 表格样式。不得将整份 Markdown HTML 未经结构化地塞进插槽，也不得在内容片段中新增局部 CSS。

主页顺序：

1. 业务标题、方案摘要；其下直接显示需求文档和项目外部参考资料的可点击链接。
2. 整体流程讲解：左侧阶段导航、中间纵向数据流程图、右侧当前阶段详情及读写对象。完整图随阶段阅读保持可见；滚动、点阶段或点节点均同步高亮导航、图中阶段和详情。阶段高亮使用可辨识的底色与描边，不能把其他节点和线灰化。
3. 所有可单独讲解的业务逻辑：每项标题和一句结论常显，细节在原位展开；不弹侧栏、不跳页。
4. 数据对象：以“对象作用为行、适用范围为列”对齐分区展示。范围来自输入；对象完整写明库和表、用途及适用范围。对象区独立于流程图，不用卡片或 HTML 表格。
5. 字段血缘：逐目标字段说明业务含义、来源字段、推导规则、阶段和已知边界。
6. 来源说明及相关文档链接。

页面区域和顺序固定；某项内容不存在时保留该区域并简要写“来源未提供”或“待确认”，不随项目省略、重排或用其他内容填空。完整规格页只按用户明确要求另行生成，不改变主页骨架。

主图/阶段/详情联动应从同一 manifest 派生；每条来源关系必须映射到总图或关联的阶段细节图。复杂图可以抽象总览，但不得丢失分支、并行路径或关系。阶段、节点、连线、读写对象及逻辑专题均可追溯至规格 Markdown。

对象行按输入识别来源、配置、中间、结果等作用；列按输入识别正式/测试、地域、版本等范围，不预设固定值。一个范围也保留明确列名；未知则标“待确认”。使用模板中的 CSS Grid 二维矩阵，不用卡片、对象列表或 HTML `<table>` 替代。矩阵使用带 `role="table"` 的容器、`role="row"` 的行容器和 `columnheader` / `rowheader` / `cell` 语义；每个交叉单元格只放该作用和范围下的对象。正式与测试对象分开，不把一段混合描述复制到多个格子。对象缺失或关系不明时保留格子并标“未提供”或“待确认”，不推断另一环境存在同名表。说明方案目标与 DDL 定义对象的差异；DDL 只说明结构，不证明实际部署状态。

## 可选完整规格页

仅用户明确要求时，从同一规格 Markdown 另生成完整规格页，并与主页互链。保留范围内细节，按原章节阅读；不复制主页三栏布局。

## 页面边界

这是数据方案展示，不写实现 SQL 或 SQL 文件清单、测试/验证、进度、执行/部署状态、运维、数据使用者说明。已有或设计中的 DDL 可以链接；处理逻辑只写方案，不写实现 SQL。项目内来源 Markdown 可链接；外部参考链接紧随标题摘要显示。

HTML 自包含、离线可读，面向电脑端。按图和内容扩宽页面；流程图栏内不得横向拖动。保留无脚本时可读的主要内容、键盘焦点和减少动态效果支持。

## 固定视觉与结构检查

- 页面固定为：吸顶主导航；标题、摘要及需求/参考链接；左侧阶段导航 / 中间总流程图 / 右侧阶段详情的同步讲解区；关键业务逻辑；数据对象矩阵；字段血缘；方案来源。
- 使用模板已有的浅色背景、深色正文、蓝色当前阶段、固定中文系统字体栈、16px 正文基线和一致的标题/间距层级。业务国家、产品或来源不同，不另换配色和圆角卡片风格；图的语义色按[锁定的 diagram-design profile](diagram-design.md)。
- 三栏讲解区随阶段标记滚动：阶段导航、中间流程图、右侧详情各自固定在可视区内；阶段数或详情长度增加时，仅对应栏内部纵向滚动，主页面流程区不被内容撑偏。阶段导航、图中阶段底色、活动节点和右侧详情同步；每次只显示一个阶段详情。切换阶段时，阶段导航滚到当前项、流程图滚到当前节点、右侧详情回到顶部。每个 SVG 阶段背景使用 `data-stage-band`，节点使用 `data-stage-node`，节点外框使用 `data-node-outline`，阶段标记、导航和详情分别使用 `data-stage-marker`、`data-stage-link`、`data-stage-detail`；它们使用同一稳定阶段键。流程节点可用鼠标及 Enter/空格键激活。活动阶段只增加蓝色浅底和描边，图中其他节点与连线维持原有语义颜色。页面滚出阶段讲解区后按普通文档滚动。
- 主流程每条有向关系使用无箭头的静态连线和沿同一路径运动的连续短线段；短线段使用 `data-flow-motion`，以便减少动态效果时关闭。静态连线始终完整可见；图中不能只放一个光点表示整条数据流。
- 图中颜色、字体、画布宽度、节点大小、线宽和动效参数来自模板及[diagram-design profile](diagram-design.md)。SVG 固定 `viewBox` 宽度和页面最大显示宽度为 960；画布高度随真实拓扑纵向增长。图中文字使用本地中文字体，主节点 20px、辅助说明 16px；不按项目另挑尺寸预设或修改 SVG 比例来缩小文字。主流程可纵向滚动，当前阶段切换时图自动将对应节点移入可视区，任何祖先容器都不得裁切 SVG。
- 对象矩阵的第一列为作用，后续列为输入实际给出的范围。即使只有一个范围也保留范围表头；列数动态变化，不固定为正式/测试两列。矩阵使用无卡片边框的对齐分区。
- 输出前运行 [`scripts/validate_html.py`](../scripts/validate_html.py)，并传入已安装 diagram-design skill 的 `scripts/self_check.py` 路径。校验器会抽取主流程 SVG 单独运行上游自检，避免页面阶段联动脚本干扰；同时核对主页 CSS/JS 与模板一致、无残留占位符、阶段键对应、对象范围列数、流程图无箭头且静态线/动效线成对、画布规格固定。再按上游几何规则检查交叉、重叠、文字越界；最后按内容清单人工核对事实和来源是否齐全。缺少事实时明确标注，不以推断补齐。这些检查只针对文档呈现，不检查 SQL、数据库或业务结果。
