# 数据开发文档 · data-development-docs

一个面向数据管道、数仓建模、ETL 和分析需求的 Agent Skill。把业务口径、加工逻辑、表关系和字段血缘整理成内容一致的 **Markdown 源文档 + 交互式 HTML 阅读版**，方便业务、开发、测试和项目管理共同评审。

它是一套指导 AI 助手执行的文档工作流，不是独立运行的文档生成程序。技能入口与界面简介已中文化；详细执行规则和参考规范保留英文。

## 能解决什么问题

- **看得懂业务**：先解释业务目标、范围和规则，再展开技术方案。
- **查得到字段**：从目标字段追溯来源、转换、关联、过滤、粒度以及空值和冲突处理。
- **分得清阶段**：目标方案、开发进度、测试证据按职责分开；多页面通过统一总览导航。
- **说得清加工**：每个独立计算都有明确逻辑块及对应图示，多源选举与属性融合分别表达。
- **讲得全生命周期**：说明全量与增量读取范围、软删除发现、源状态撤回和下游结果清理。
- **方便交互阅读**：使用连续数据流图、上下文详情和字段检索，支持键盘操作及减少动态效果。

## 快速使用

在支持此技能格式的助手中加载整个技能目录，然后提交：

```text
使用 $data-development-docs，阅读当前项目的需求、SQL 和 DDL，
生成中文目标方案文档 docs/solution.md 和 docs/solution.html。
说明业务口径、加工逻辑块、表关系、字段血缘及全量/增量边界。
待确认问题明确标注，方案页不包含开发进度和测试结果。
```

安装、输入准备与不同场景的完整提示词见 [使用指南](docs/usage.md)。

## 交付内容

| 交付物 | 回答的问题 |
| --- | --- |
| Markdown 源文档 | 规则是什么、字段从哪里来、经过什么加工？ |
| 自包含 HTML 阅读版 | 如何沿着数据流快速浏览并逐层查看细节？ |
| 多页文档总览（按需） | 应该打开哪份方案、进度或测试文档？ |

HTML 默认内联 CSS、JavaScript 和 SVG，避免远程资源依赖。文档内容由助手结合项目证据生成；本仓库不包含固定生成器，也不承诺每次输出相同版式。

## 依赖与边界

基础工作流需要助手能够读取项目文件并写出 Markdown/HTML。浏览器用于实际页面与交互验收，HTML 解析器和 JavaScript 语法检查工具用于结构检查；缺少浏览器时应明确说明视觉验证未完成。

`data-grilling` 和 `diagram-design` 是相关场景下可复用的技能，本仓库不附带它们。规则存在业务歧义时可使用前者，复杂图示可使用后者；使用前先检查当前环境是否提供。

本技能负责文档，不自动部署 ETL、修改生产数据库或证明加工已上线。真实表结构、逻辑设计、观测证据和待确认事项需要明确区分。
